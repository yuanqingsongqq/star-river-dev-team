# PRD 需求文档技能

## 触发场景

当需要以下任务时使用此技能：
- 编写产品需求文档
- 分析用户需求
- 编写用户故事
- 定义验收标准
- 需求评审

## 核心能力

### 1. PRD 结构模板

```markdown
# 产品需求文档 (PRD) - {功能名称}

## 1. 概述

### 1.1 背景
[为什么需要这个功能]

### 1.2 目标
[通过这个功能要达到什么目标]

### 1.3 范围
- **包含**：
- **不包含**：

## 2. 用户分析

### 2.1 目标用户
[谁是主要用户]

### 2.2 用户画像
```
姓名：
角色：
目标：
痛点：
```

### 2.3 使用场景
| 场景 | 用户 | 目标 | 触发 |
|------|------|------|------|
| ... | ... | ... | ... |

## 3. 功能需求

### 3.1 功能清单
| ID | 功能 | 优先级 | 描述 |
|----|------|--------|------|
| F1 | ... | P0 | ... |

### 3.2 详细需求

#### F1: {功能名称}
**描述**：...
**用户故事**：
```
作为 [用户类型]
我想要 [功能]
以便 [价值]
```

**验收标准**：
- Given [前置条件]
- When [操作步骤]
- Then [预期结果]

**边界情况**：
- ...
```

## 4. 非功能需求

### 4.1 性能要求
- 响应时间 < Xs
- 并发支持 X 用户

### 4.2 安全要求
- ...

### 4.3 兼容性
- ...

## 5. 需求变更记录
| 日期 | 变更内容 | 变更原因 | 审批人 |
|------|---------|---------|--------|
| ... | ... | ... | ... |
```

### 2. 用户故事模板

```markdown
## 用户故事 - {ID}

**故事标题**：...

**故事描述**：
```
作为 [用户类型]
我想要 [功能/行为]
以便 [价值/收益]
```

**验收标准 (ATDD)**：
| 场景 | Given | When | Then |
|------|-------|------|-------|
| 正常 | 前置条件 | 操作 | 结果 |
| 异常 | ... | ... | ... |

**优先级**：P0 / P1 / P2 / P3
**故事点**：X
**依赖**：US-XXX
```

### 3. MoSCoW 优先级

| 级别 | 含义 | 必须完成 |
|------|------|----------|
| **M**ust have | 必须有 | ✅ MVP |
| **S**hould have | 应该有 | ✅ 重要 |
| **C**ould have | 可以有 | ⚪ 可选 |
| **W**on't have | 不会有 | ❌ 本期不做 |

### 4. 需求评审检查清单

- [ ] 需求清晰，无歧义
- [ ] 每个需求有明确的验收标准
- [ ] 优先级已确定
- [ ] 依赖关系已明确
- [ ] 技术可行性已确认
- [ ] UX 设计已评审
- [ ] 测试可执行性已确认
```
